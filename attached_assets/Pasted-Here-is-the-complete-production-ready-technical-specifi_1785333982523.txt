Here is the complete, production-ready technical specification and architectural blueprint for our new custom ecommerce platform. We are bypasssing third-party ecosystems like Shopify completely to maintain 100% data ownership.Please use this comprehensive brief to select the exact frameworks, initialize your database migrations, and begin active development immediately.1. High-Level Vision & Core StackWe are building a bespoke, headless ecommerce platform capable of handling a very large inventory (tens of thousands of SKUs) with sub-second page loads.The UX/UI Benchmark: Expanse by Archetype Themes. This is our gold standard for storefront discovery. It features instant multi-attribute sidebar filtering, deep mega-menus, and an asynchronous, conversion-heavy slide-out cart drawer.The Backend & Database: Supabase (PostgreSQL) for data storage, authentication, and real-time listeners.The Hosting Infrastructure: Railway to host our custom Node.js/Go backend API services, workers, and background queues.The Discovery Engine: Meilisearch (Open-Source/Free Self-Hosted) for ultra-fast catalog search and filtering.The Payment Ecosystem: Localized Kenyan payment integrations (M-Pesa Express/STK Push via Safaricom Daraja API, paired with Pesapal or Flutterwave as a card/hybrid gateway fallback).2. Frontend Architecture (Islands & Hydration Strategy)To match the performance of the Expanse theme, we must keep Total Blocking Time (TBT) near zero. Avoid large monolithic SPA bundles.Framework Requirement: Use Next.js (App Router) or Astro.Implementation: Deliver fully server-side rendered (SSR) or statically generated (SSG) HTML for core product listings and static assets. Isolate interactive features—like the quick-buy modal, search dropdowns, and slide-out cart drawer—into lightweight, client-side hydrated "islands."State Management: Use a lightweight, atomic state manager like Zustand to control the global cart state, slide-out drawer transitions, and live dynamic cross-sell prompts without triggering full-page re-renders.3. Database Schema & Real-Time Admin EngineWe are managing a fully relational database instance on Supabase. Your first task will be drafting the database migrations.The Database Blueprint: Build a highly normalized PostgreSQL schema. You must cleanly structure tables for products, product_variants (handling the size/color/price matrix), inventory_levels (tracked per variant), customers, orders, and order_items.Backoffice Admin Portal: Build a protected internal dashboard within the application workspace for inventory tracking, order fulfillment, and metrics visualization.Real-Time Subscriptions: Leverage Supabase Realtime on the Admin dashboard. Incoming orders, system updates, and low-stock indicators must stream instantly to the UI without pulling data via manual refresh requests.Access Management: Implement strict Role-Based Access Control (RBAC) via PostgreSQL Row-Level Security (RLS) policies. Warehouse dispatchers must only see fulfillment streams, while finance/admin accounts access margins and price updates.4. Self-Hosted Discovery (Meilisearch Engine)Because standard SQL LIKE queries will choke on tens of thousands of SKUs during complex multi-attribute sidebar filtering, we are leveraging the open-source version of Meilisearch.Deployment: Deploy a self-hosted instance of Meilisearch on Railway alongside our core applications to utilize the free tier/resource allocation efficiently.Asynchronous Sync Pipeline: Write a Supabase Database Webhook or listen to the PostgreSQL Write-Ahead Log (WAL) using a background worker on Railway. Any INSERT, UPDATE, or DELETE on the products or product_variants tables must fire an asynchronous payload to update the Meilisearch index instantly.5. Kenyan Payment Processing State MachinePayment transactions must be reliable, especially when handling mobile money networks like M-Pesa.M-Pesa Core Integration: Implement the Safaricom Daraja API. When a user clicks "Checkout", trigger an asynchronous STK Push (Lipanampesa Online) request directly to their phone.Gateway Fallback: Layer Pesapal or Flutterwave alongside Daraja to safely process local Visa/Mastercard payments and bank transfers.Atomic Transactions: When a payment confirmation webhook arrives from Safaricom or Pesapal, processing must occur inside a strict PostgreSQL Database Transaction (BEGIN / COMMIT). You must explicitly verify payment validation, create the immutable order ledger record, and decrement the specific variant inventory_levels atomically. This is non-negotiable to prevent race conditions (over-selling the last stock unit if two users push STK PINs simultaneously).6.
